1. Đường đi của /api/v1/auth/signin hiện tại

Endpoint mà FE gọi là:

@app.post(f"{settings.API_V1_PREFIX}/auth/signin", response_model=SignInResponse)
async def simple_signin(request: SignInRequest, db: DatabaseManager = Depends(get_database)):
    ...


Khi gọi /api/v1/auth/signin, pipeline thực tế như sau:

(A) Middleware activity logging chạy trước

ActivityLoggingMiddleware được add vào app:

if ACTIVITY_AVAILABLE:
    app.add_middleware(ActivityLoggingMiddleware, db_manager=db_manager)
    logger.info("Activity logging middleware enabled")


Trong middleware:

Đọc body của request để log:

if request.method in ["POST", "PUT", "PATCH"]:
    body = await request.body()
    if body:
        request_payload = json.loads(body)
        ...


Gọi response = await call_next(request) → lúc này mới chạy vào simple_signin.

Sau khi có response, middleware lại query DB để xem table log có tồn tại không:

table_check = await self.db_manager.execute_query(
    "SELECT EXISTS (SELECT FROM information_schema.tables "
    "WHERE table_schema = 'iam' AND table_name = 'user_activity_logs')"
)


Nếu tồn tại, nó INSERT log vào iam.user_activity_logs qua ActivityLogger.log_activity (thêm 1 query nữa):

Tóm lại: mỗi request (kể cả signin) đều:

1 SELECT ... information_schema...

1 INSERT ... user_activity_logs (nếu table tồn tại)

(B) Bên trong handler simple_signin

Trong simple_signin:

Query user từ DB (hàm authenticate_user_db) → ít nhất 1 SELECT (user) + 1 SELECT (role).

bcrypt.checkpw để verify password (tương đối nặng CPU trên free instance).

Update last_login thông qua IAMService.update_last_login → 1 UPDATE nữa:

Ghi log hoạt động đăng nhập lần thứ 2 bằng ActivityLogger.log_activity → 1 INSERT nữa:

=> Tổng số round-trip tới DB cho 1 lần signin (khi Activity logging bật):

1 SELECT information_schema (middleware)

1 SELECT user (auth)

1 SELECT roles (auth)

1 UPDATE last_login

1 INSERT activity_log (trong handler)

1 INSERT activity_log (trong middleware)

~5–6 query + bcrypt trên Render (qua SSL, network xa, free tier CPU) → rất dễ bị >5–10s, nhất là lần đầu hoặc khi DB idle.

Trên local thì tất cả đều rất nhanh nên bạn không cảm nhận được.

2. Tại sao Render dễ bị “load lâu”

Một số lý do thực tế:

Postgres Render + SSL
Trong lifespan, bạn luôn bật SSL "require" cho DB Render:
Mỗi query đều phải đi qua network + SSL handshake/IO → latency cao hơn local rất nhiều.

Nhiều query liên tiếp trong 1 request như phân tích ở trên.

Free plan / shared CPU
Nếu service “thức dậy” (cold start) hoặc đang bị share CPU, mỗi query/bcrypt càng tốn thời gian → FE cảm giác “load mãi”.

Activity logging làm “nặng” riêng route signin
Bạn vừa log trong middleware, vừa log trong handler → double work cho cùng 1 request.

3. Việc nên làm ngay để kiểm chứng & giảm lag
Bước 1: Test nhanh xem có phải do DB / logging không

Tạm thời tắt activity logging middleware trong main.py:

# if ACTIVITY_AVAILABLE:
#     app.add_middleware(ActivityLoggingMiddleware, db_manager=db_manager)
#     logger.info("Activity logging middleware enabled")
# else:
#     logger.warning("Activity logging middleware disabled - module not available")


Deploy lại và test /api/v1/auth/signin:

Nếu login nhanh hẳn → chắc chắn bottleneck chính là middleware + log DB.

Nếu vẫn chậm → tới bước 2.

Bước 2: Giảm số lần query cho riêng signin

Chỉ log 1 nơi: hoặc middleware, hoặc trong handler simple_signin, không nên cả hai.

Cá nhân mình gợi ý:

Đối với signin/signout, giữ log trong handler (vì bạn có đủ context như method, role, email…).

Trong middleware, bỏ log cho auth bằng cách thêm path vào skip:

skip_paths = [
    "/docs", "/openapi.json", "/health", "/favicon.ico", "/static",
    "/api/v1/auth/signin", "/api/v1/auth/signout", "/api/v1/auth/signup"
]


Bỏ check “table_exists” mỗi request

Đoạn này đang query information_schema cho mọi request:

table_check = await self.db_manager.execute_query(
    "SELECT EXISTS (SELECT FROM information_schema.tables WHERE table_schema = 'iam' AND table_name = 'user_activity_logs')"
)


Cách tối ưu:

Check một lần khi startup (lúc init app) rồi lưu vào biến global, vd: ACTIVITY_TABLE_READY = True/False.

Trong middleware chỉ cần if ACTIVITY_TABLE_READY: là đủ, không gọi query nữa.

Bước 3: Thêm log đo thời gian trong simple_signin

Để thấy rõ phần nào chậm, bạn thêm đo thời gian:

import time

@app.post(f"{settings.API_V1_PREFIX}/auth/signin", response_model=SignInResponse)
async def simple_signin(request: SignInRequest, db: DatabaseManager = Depends(get_database)):
    t0 = time.time()
    logger.info(f"Simple signin attempt for: {request.email}")

    t_auth_start = time.time()
    user_data = await authenticate_user_db(request.email, request.password, db)
    logger.info(f"Auth DB done in {time.time() - t_auth_start:.3f}s")

    if not user_data:
        user_data = authenticate_user(request.email, request.password)
    if not user_data:
        raise HTTPException(status_code=401, detail="Invalid credentials")

    t_last_login = time.time()
    try:
        from app.services.iam_service import IAMService
        iam_service = IAMService(db)
        await iam_service.update_last_login(user_data["user_id"])
    except Exception as e:
        logger.error(f"Failed to update last login: {e}")
    logger.info(f"Update last_login done in {time.time() - t_last_login:.3f}s")

    t_log = time.time()
    try:
        if ACTIVITY_AVAILABLE and ActivityLogger:
            activity_logger = ActivityLogger(db)
            await activity_logger.log_activity(
                user_id=user_data["user_id"],
                email=user_data.get("email", request.email),
                action="USER_SIGNIN",
                request_path="/api/v1/auth/signin",
                details={"role": user_data.get("role", "unknown"), "method": "password"},
                status="success"
            )
    except Exception as e:
        logger.error(f"Failed to log signin activity: {e}")
    logger.info(f"Signin activity log done in {time.time() - t_log:.3f}s")

    logger.info(f"Total signin handler time: {time.time() - t0:.3f}s")
    ...


Sau khi deploy Render, xem log:

Nếu Auth DB done ~2–3s, Signin activity log ~2–3s → trai đẹp là query DB chậm.

Nếu Total signin handler time <1s mà FE vẫn chờ lâu → vấn đề ở client, network, CORS, hoặc proxy.

Bước 4: Một vài tối ưu nhỏ khác

Không import IAMService mỗi request

Hiện tại bạn import trong hàm:

from app.services.iam_service import IAMService
iam_service = IAMService(db)


Import trong Python có cache, nên không phải cực kỳ nặng, nhưng tốt nhất vẫn đưa lên trên file, giữ cho handler nhẹ hơn.

Giảm số query trong authenticate_user_db

Gộp lấy user + role vào 1 query (JOIN) thay vì 2 query tách.

Kiểm tra /debug connection trên Render

Bạn đã có endpoint /debug/connection trong main.py (trước đây mình thấy bạn có). Gọi thử để xem thời gian query đơn giản (SELECT 1). Nếu SELECT 1 mất >500ms trên Render thì mọi query khác sẽ càng tệ.

4. Tóm lại

Từ code và log:

App startup ok, pool DB Render ok, không lỗi.

/api/v1/auth/signin hiện đang:

bị chạy qua middleware log (đọc body, query information_schema, ghi log DB),

bên trong handler lại query DB 3–4 lần + bcrypt + ghi log lần nữa.

→ Trên Render (SSL + network xa + free tier) dễ khiến signin cực chậm hoặc time-out.

Hướng xử lý cụ thể:

Tạm tắt ActivityLoggingMiddleware để xác nhận bottleneck.

Sau đó:

Bỏ log duplicate (chỉ log ở 1 chỗ),

Bỏ check information_schema mỗi request,

Bỏ middleware cho các path /api/v1/auth/* nếu cần.

Thêm log đo thời gian từng bước trong simple_signin để thấy đoạn nào chậm nhất.
