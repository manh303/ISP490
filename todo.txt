1. Price DSS – /dss/price/run
1.1. Ở hàm run_price_prediction_dss (tầng service tổng)

Mục tiêu: đừng ép min_confidence, lưu lại request đúng như Analyst nhập.

Bước 1 – Đừng override min_confidence quá mạnh

Hiện tại đoạn normalize request kiểu:

req["page_size"] = min(req.get("page_size", 50), 100)
req["top_n"] = min(req.get("top_n", 50), 100)
req["min_confidence"] = max(req.get("min_confidence", 0.70), 0.6)


→ Bạn nên sửa thành:

req["page_size"] = min(req.get("page_size", 50), 100)
req["top_n"] = min(req.get("top_n", 50), 100)

# Giữ nguyên giá trị user gửi, chỉ clamp trong khoảng 0–1
min_conf = req.get("min_confidence", 0.7)
req["min_confidence"] = max(0.0, min(min_conf, 1.0))


Ý: Analyst nhập 0.4 thì cho phép 0.4, đừng auto đẩy lên 0.6.

Bước 2 – Chuẩn hoá from_date/to_date

Trước khi gọi _query_price_predictions, nên convert string → date (nếu chưa):

from datetime import datetime

for key in ["from_date", "to_date"]:
    if isinstance(req.get(key), str):
        req[key] = datetime.strptime(req[key], "%Y-%m-%d").date()

1.2. Ở _query_price_by_category – dùng đúng khoảng ngày + data thật

Mục tiêu:

Thay product_metrics_global bằng aggregate từ fact_product_daily có join dim_date.

Dùng prediction_confidence nếu đã có.

Bắt đầu chuẩn bị để áp max_discount_pct, min_margin_pct.

Bước 3 – Thêm CTE product_metrics_windowed

Trong SQL hiện tại bạn có join dwh.product_metrics_global pm. Giờ sửa thành:

WITH date_bounds AS (
    SELECT 
        $from_date::date AS from_date,
        $to_date::date   AS to_date
),
product_metrics AS (
    SELECT
        f.product_sk,
        f.platform_sk,
        AVG(f.avg_price)       AS avg_price,
        MIN(f.min_price)       AS min_price,
        MAX(f.max_price)       AS max_price,
        SUM(f.total_review_count) AS total_reviews,
        AVG(f.avg_rating)      AS avg_rating,
        SUM(f.total_orders)    AS total_orders,
        SUM(f.total_revenue)   AS total_revenue
    FROM dwh.fact_product_daily f
    JOIN dwh.dim_date dd ON dd.date_sk = f.date_sk
    JOIN date_bounds db ON dd.date_value BETWEEN db.from_date AND db.to_date
    GROUP BY f.product_sk, f.platform_sk
),
ranked_predictions AS (
    ...
)


Rồi ở phần filtered_results:

LEFT JOIN product_metrics pm
    ON pm.product_sk = latest_predictions.product_sk
   AND pm.platform_sk = latest_predictions.platform_sk


→ Bỏ join với dwh.product_metrics_global.

Như vậy mọi metric avg_price, total_reviews, total_orders, total_revenue đều “đúng khoảng thời gian” mà Analyst chọn.

Bước 4 – Dùng prediction_confidence thay vì tính từ CI

Trong latest_predictions hiện đang:

latest_predictions AS (
    SELECT
        product_sk,
        platform_sk,
        predicted_price,
        ci_upper,
        ci_lower,
        created_at,
        GREATEST(0.0, LEAST(1.0,
            1.0 - (ci_upper - ci_lower) / NULLIF(predicted_price, 0)
        )) AS confidence
    FROM ranked_predictions
    WHERE rn = 1
)


Sửa thành:

latest_predictions AS (
    SELECT
        product_sk,
        platform_sk,
        predicted_price,
        ci_upper,
        ci_lower,
        created_at,
        COALESCE(prediction_confidence,
                 GREATEST(0.0, LEAST(1.0,
                   1.0 - (ci_upper - ci_lower) / NULLIF(predicted_price, 0)
                 ))
        ) AS confidence
    FROM ranked_predictions
    WHERE rn = 1
)


Giả sử bạn đã sửa run_price_predictions.py để fill cột prediction_confidence rồi.

Bước 5 – Áp min_confidence, min_price_change_pct, max_discount_pct, min_margin_pct

Trong WHERE của CTE filtered_results, hiện bạn đã có filter:

WHERE
    pm.avg_price > 0
    AND latest_predictions.confidence >= $min_confidence
    AND ABS(latest_predictions.predicted_price - pm.avg_price) / pm.avg_price >= $min_price_change_pct


Giờ:

Clamp giảm giá tối đa (max_discount_pct):

Nếu bạn muốn làm ở SQL: chỉ nhận những rec mà giá đề xuất không thấp hơn một ngưỡng:

AND (latest_predictions.predicted_price >= pm.avg_price * (1 - $max_discount_pct))


Hoặc nếu làm ở Python layer sau khi fetch rows: chỉnh recommended_price = max(recommended_price, current_price * (1 - max_discount_pct)) rồi recalc diff.

Áp min_margin_pct nếu đã có avg_margin_pct:

Nếu đã thêm avg_margin_pct vào product_metrics (hoặc join product_metrics_global chỉ để lấy margin):

AND COALESCE(pm.avg_margin_pct, 0) >= $min_margin_pct


Nếu chưa có margin thật → tạm thời đừng dùng min_margin_pct, ghi chú “chưa áp dụng”.

Bước 6 – Tính current_orders, current_revenue từ cột mới thay vì “fake”

Trong SELECT filtered_results, hiện đang làm:

current_orders = scale từ review + random/hash.

current_revenue = current_orders * avg_price.

Giờ bạn đã có pm.total_orders, pm.total_revenue trong khoảng from/to. Nên:

pm.total_orders      AS current_orders,
pm.total_revenue     AS current_revenue,
CASE 
  WHEN pm.total_revenue IS NOT NULL AND pm.total_revenue > 0
  THEN pm.total_revenue * (latest_predictions.predicted_price / NULLIF(pm.avg_price, 0))
  ELSE NULL
END AS projected_revenue,
...


Nếu total_revenue toàn kỳ, có thể dùng luôn; nếu bạn muốn “per day” thì chia thêm, nhưng đồ án dùng tổng là được.

expected_revenue_change_pct vẫn = predicted_price / avg_price - 1.

1.3. Ở _query_price_by_product_keys – làm giống by_category

Bước 7 – Dùng lại “product_metrics_windowed”

Trong _query_price_by_product_keys, tạo CTE product_metrics giống Bước 3 nhưng filter theo:

WHERE dd.date_value BETWEEN $from_date AND $to_date
  AND dp.product_key = ANY($product_keys)


Sau đó join product_metrics pm với latest_predictions y hệt by_category.

Bước 8 – Không dùng product_metrics_global nữa

Đảm bảo không còn join dwh.product_metrics_global pm ở cuối.

Bước 9 – Áp các rule y chang by_category

min_confidence, min_price_change_pct, max_discount_pct, min_margin_pct → logic giống hệt _query_price_by_category để tránh 2 luồng khác nhau.

1.4. Ở _calculate_price_kpis – dùng revenue thật

Hiện tại KPI function đang tính:

num_products, num_with_recommendation, current_total_revenue, projected_total_revenue, expected_revenue_uplift_pct, avg_confidence…

Sau khi bạn đổi query:

current_revenue = pm.total_revenue → sum lên.

projected_revenue = pm.total_revenue * (predicted / avg_price) → sum lên.

Bước 10 – Đảm bảo:

current_total_revenue = sum(item["current_revenue"] for item in items if item["current_revenue"] is not None)
projected_total_revenue = sum(item["projected_revenue"] for item in items if item["projected_revenue"] is not None)

expected_revenue_uplift_pct = (
    (projected_total_revenue / current_total_revenue - 1.0)
    if current_total_revenue > 0 else 0.0
)

2.3. Ở _query_recommendations_by_category

Bước 5 – Top-K “per source” thay vì top-K global

Thay vì LIMIT top_k toàn bộ, bạn nên dùng window:

SELECT * FROM (
   SELECT
      ...,
      ROW_NUMBER() OVER (
          PARTITION BY rec.source_product_sk
          ORDER BY rec.similarity_score DESC, COALESCE(rec.co_purchase_rate, 0) DESC
      ) AS rn
   FROM ...
   WHERE ...
) ranked
WHERE ranked.rn <= $top_k


=> Mỗi sản phẩm nguồn có tối đa top_k gợi ý.

3. Sentiment DSS – /dss/review/run
3.1. Ở _query_review_sentiment

Mục tiêu: dùng đúng from_date / to_date → chỉ lấy review trong khoảng đó.

Giả sử dwh.fact_review có date_sk.

Bước 1 – Thêm join với dim_date và filter theo ngày

Trong CTE review_stats:

WITH review_stats AS (
    SELECT
        r.product_sk,
        COUNT(*) AS total_reviews,
        SUM(CASE WHEN sent.sentiment_label = 'positive' THEN 1 ELSE 0 END) AS positive_count,
        SUM(CASE WHEN sent.sentiment_label = 'neutral' THEN 1 ELSE 0 END)  AS neutral_count,
        SUM(CASE WHEN sent.sentiment_label = 'negative' THEN 1 ELSE 0 END) AS negative_count,
        AVG(r.rating) AS avg_rating,
        ...
    FROM dwh.fact_review r
    LEFT JOIN ml.fact_review_sentiment sent
           ON sent.review_id = r.review_sk
          AND sent.model_sk = $model_sk
    JOIN dwh.dim_date dd ON dd.date_sk = r.date_sk
    LEFT JOIN dwh.dim_platform dpl ON ...
    LEFT JOIN dwh.dim_product dp ON ...
    LEFT JOIN dwh.dim_category dc ON ...
    WHERE
        dd.date_value BETWEEN $from_date AND $to_date
        AND {platform/category filters}
    GROUP BY r.product_sk
    HAVING COUNT(*) >= $min_reviews_per_product
)


Nếu bạn đang gắn platform_code và category filter trong where_clause dynamic thì chỉ cần chèn thêm dd.date_value BETWEEN vào đó, nhớ điều chỉnh thứ tự param.

Bước 2 – Cập nhật danh sách params để include from/to

Ở phần Python build query:

Thêm from_date & to_date vào params ngay sau model_sk (hoặc thứ tự bạn chọn).

Đảm bảo $ index trong SQL khớp.

3.2. Xử lý sentiment_focus ở Python

Bước 3 – Giữ như hiện tại nhưng cho phép Analyst tinh chỉnh

Hiện tại logic:

if sentiment_focus == "only_negative":
    data = [p for p in data if p["is_critical"]]
elif sentiment_focus == "only_positive":
    data = [p for p in data if p["positive_pct"] >= 0.7]


Gợi ý:

Cho phép FE gửi thêm:

positive_threshold (default 0.7)

Dùng:

positive_threshold = request.get("positive_threshold", 0.7)
...
elif sentiment_focus == "only_positive":
    data = [p for p in data if p["positive_pct"] >= positive_threshold]

3.3. “Reasons” – giữ lại nhưng rõ ràng hơn

Ngay sau khi bạn tạo top_negative_reasons / top_positive_reasons từ review text:

Bước 4 – Nếu không có text, gắn lý do business rõ ràng

if not top_negative_reasons:
