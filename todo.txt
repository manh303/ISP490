1. Mục tiêu của Activity Log

Ghi lại mọi hành động quan trọng mà user thực hiện trong hệ thống.

Giúp Admin:

Điều tra “ai đã làm gì, lúc nào, ở đâu”.

Kiểm tra các thao tác nhạy cảm (tạo user, đổi role, xóa data, gọi API ML,…).

Phục vụ audit / báo cáo cho thầy / hội đồng: hệ thống có theo dõi & kiểm soát.

2. Từ góc nhìn Admin – Flow màn hình (Step by Step)
Step 0 – Điều kiện để dùng

Admin đã:

Đăng nhập thành công.

Có quyền: VIEW_ACTIVITY_LOG.

Menu bên trái (sidebar) có item: “Activity Log” trong nhóm “System / Security”.

Step 1 – Admin mở màn Activity Log

Admin click menu “Activity Log”.

FE gọi API, ví dụ:

GET /api/v1/admin/activity-logs?limit=20&page=1&sort=-created_at

Hệ thống trả về danh sách log mới nhất.

UI chính: 1 bảng (table) với các cột:

Time: Thời điểm xảy ra (Ví dụ: 2025-12-01 10:25:13).

User: Email hoặc full_name (ví dụ: user@example.com (Analyst)).

Role: Role chính hiện tại của user lúc thực hiện hành động (admin, analyst, ml_engineer,…).

Action: Hành động ngắn gọn (ví dụ: LOGIN_SUCCESS, CREATE_USER, UPDATE_ROLE, EXPORT_REPORT, CALL_ML_MODEL…).

Module: Phần hệ thống (ví dụ: IAM, ANALYTICS, DSS, ML, DATA_PIPELINE…).

Resource: Tài nguyên cụ thể (ví dụ: iam_user#123, ml_model#price_forecast_v1.0…).

Status: SUCCESS / FAILED.

IP / User Agent (optional): IP của client, trình duyệt.

More / Detail: nút “View” hoặc icon 👁 để xem chi tiết log.

Step 2 – Filter cơ bản để điều tra nhanh

Ở phía trên bảng là các filter:

Khoảng thời gian (Date range)

Từ ngày – đến ngày (mặc định là Today hoặc 7 ngày gần nhất).

FE gửi query: from=2025-11-25&to=2025-12-01.

User / Email

Input search: gõ email hoặc 1 phần tên.

Query: user_email=user@example.com hoặc keyword=manh.

Role

Dropdown: Admin, Analyst, ML Engineer, Data Engineer, Customer.

Query: role=admin.

Action Type

Dropdown multi-select: LOGIN, LOGOUT, CREATE_USER, UPDATE_USER, DELETE_USER, CHANGE_ROLE, EXPORT_REPORT, RUN_MODEL, UPDATE_MODEL_CONFIG,…

Query: action=CREATE_USER hoặc action=LOGIN_FAILED.

Module

Dropdown: IAM, Analytics, DSS, ML, DataPipeline.

Query: module=IAM.

Status

ALL / SUCCESS / FAILED.

Query: status=FAILED.

Full-text search (Keyword)

Tìm trong request_path, resource_id, detail_message.

Ví dụ: gõ “price_forecast_v1.0”, gõ “tiki_459201”, “dim_product”.

Flow sử dụng:

Admin chọn Date range = hôm nay, module=IAM, action=CREATE_USER.

Bấm Search / Apply filter.

Bảng reload, hiển thị đúng subset log.

Step 3 – Xem chi tiết 1 Activity Log

Khi Admin nghi ngờ 1 hành động, họ cần xem chi tiết.

Admin bấm vào icon 👁 hoặc click vào dòng log.

Mở Drawer / Modal “Activity Details” bên phải.

Trong popup chi tiết có các phần:

3.1. Thông tin chung (Header)

Time: 2025-12-01 10:25:13.

User: admin@example.com.

Role tại thời điểm đó: admin.

Module: IAM.

Action: UPDATE_USER_ROLE.

Status: SUCCESS.

IP: 192.168.1.10.

User Agent: Chrome 142 / Windows.

3.2. Context / Resource

Resource type: iam_user.

Resource ID: user_id = 42.

Resource name: user42@example.com.

3.3. Request Info (nếu log)

Request method: PUT.

Request path: /api/v1/admin/users/42/roles.

Request body (masked):

{
  "old_roles": ["analyst"],
  "new_roles": ["analyst", "ml_engineer"]
}


Các field nhạy cảm (password, token) phải mask hoặc không log.

3.4. Before/After (nếu có)

Before:

roles: ["analyst"]

After:

roles: ["analyst", "ml_engineer"]

=> Admin nhìn vào biết ai đã cấp thêm quyền ML Engineer cho user này, lúc nào.

3.5. Response / Error (nếu FAILED)

Response code: 403 hoặc 500.

Error message (safe):

PermissionDenied: User 'analyst@example.com' tried to call /api/v1/admin/users without role 'admin'.

Step 4 – Phân trang, sắp xếp

Có Pagination: page 1 2 3 ..., page size: 20/50/100.

Có Sort theo:

Time (mới → cũ, mặc định).

User.

Action.

FE gửi query:

page=2&limit=50&sort=created_at_desc.

Step 5 – Export & Báo cáo

Để phục vụ báo cáo, audit hoặc nộp minh chứng:

Admin filter xong (ví dụ: 1 tuần gần nhất, module = IAM, action = CREATE_USER / UPDATE_ROLE).

Bấm nút Export (CSV/Excel).

FE gọi API, ví dụ:

GET /api/v1/admin/activity-logs/export?...(các filter)

Backend tạo file CSV/Excel và trả về link hoặc file.

Admin tải file, có thể mở bằng Excel để:

Lọc thêm.

Đưa vào báo cáo, slide, phụ lục.

Step 6 – Một số kịch bản sử dụng thực tế

Điều tra “Ai cấp quyền Admin cho user X?”

Filter:

action=UPDATE_USER_ROLE

resource=iam_user#id_of_X

Xem log, biết chính xác:

Admin nào làm.

Thời gian.

Before/After role.

Điều tra “Tại sao user bảo bị đăng nhập lỗi?”

Filter:

module=IAM

action in [LOGIN_SUCCESS, LOGIN_FAILED]

user_email=that_user@example.com

Xem chuỗi log:

Thấy nhiều LOGIN_FAILED, reason = “wrong_password”.

Hoặc lỗi ACCOUNT_LOCKED.

Kiểm tra ai đã export dữ liệu nhạy cảm

Filter:

action=EXPORT_REPORT

module=ANALYTICS hoặc DSS.

Xem:

Ai xuất.

Thời điểm.

Loại report gì (overview, review detail, price forecast…).

Theo dõi call ML model

Filter:

module=ML

Thấy:

Node nào call model.

Số lượng request.

Lỗi trong lúc chạy.

3. Từ góc nhìn hệ thống – Ghi log như thế nào (Step by Step)

Để màn Activity Log chạy được, dưới backend sẽ có luồng ghi log như sau.

Step 1 – Thiết kế bảng iam_activity_log / iam_audit_log

Ví dụ schema tối thiểu:

log_id (PK).

timestamp (timestamptz).

user_id (FK tới iam_user).

user_email (denormalize cho tiện query).

role_at_time (text / jsonb).

module (IAM / Analytics / DSS / ML / DataPipeline…).

action (LOGIN_SUCCESS, CREATE_USER, UPDATE_USER, EXPORT_REPORT,…).

resource_type (iam_user, ml_model, report, dataset,…).

resource_id (text).

request_path (text).

request_method (text).

request_payload (jsonb, optional, đã mask).

before_data (jsonb, optional).

after_data (jsonb, optional).

status (SUCCESS / FAILED).

ip_address (text).

user_agent (text).

message (text – mô tả ngắn, lỗi, note).

Step 2 – Middleware ghi log cho từng request

Mỗi lần có request tới backend:

Middleware đọc:

user_id từ JWT / session.

path, method, body.

IP, user-agent.

Xác định module + action dựa vào route:

/api/v1/admin/users → module IAM, action CREATE_USER (nếu POST).

/api/v1/analytics/... → module ANALYTICS, action tương ứng.

Sau khi xử lý xong:

Nếu không lỗi → status = SUCCESS.

Nếu raise exception → status = FAILED, log kèm error message.

Insert 1 record vào iam_activity_log.

Step 3 – Service riêng cho log

Để Admin UI gọi:

Service ActivityLogService với các method:

list_logs(filters, pagination).

get_log_detail(log_id).

export_logs(filters).

API gợi ý:

GET /api/v1/admin/activity-logs
Trả về list log (kèm meta pagination).

GET /api/v1/admin/activity-logs/{log_id}
Trả về chi tiết 1 log.

GET /api/v1/admin/activity-logs/export
Trả về file.

Step 4 – Phân quyền

Chỉ user có role admin hoặc security_admin mới xem được.

Một số log rất nhạy cảm (token, password) phải ẩn nội dung:

Chỉ show ***MASKED***.

Có thể thêm config:

Thời gian lưu log: 6 tháng / 1 năm.

Dọn log cũ bằng job định kỳ (Airflow / cron).

4. Tóm tắt ngắn gọn

Activity Log của Admin là:

1 màn hình trong Admin Panel để:

Xem bảng tất cả hoạt động.

Lọc theo thời gian, user, role, module, action, status, keyword.

Xem chi tiết từng log (before/after, request, resource).

Export ra CSV/Excel cho audit / báo cáo.

Phần backend:

Middleware + service ghi log vào bảng iam_activity_log.

API cho Admin đọc / export log.

Bảo mật & phân quyền rõ ràng.
