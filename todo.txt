Lý do AI đang trả về “thiếu dữ liệu” là vì AI nhận được rất ít / không có data, hoặc fallback rule-based không đọc đúng các KPI nên rơi vào 2 câu generic.

Để kiểm tra dữ liệu AI nhận và ép nó trả “đầy đủ” hơn, mình sẽ:

Thêm debug info trong response (ai_input_stats) để thấy AI đang được feed gì.

Thêm logging chi tiết khi bật ENV AI_DEBUG=1.

Cải thiện fallback cho price_prediction để không còn rơi vào 2 câu chung chung khi thực ra đã có KPI.

Dưới đây là từng bước sửa cụ thể.

1. Hiểu rõ hiện tại AI đang nhận gì
a) AI lấy input ở đâu?

Ở DSSService.run_product_recommendation_dss:

ai_payload = {
    **dss_result_raw,
    "table_data": dss_result_raw["table_data"][:15],
}


rồi gọi:

ai_result = self.ai_summarizer.summarize_with_ai(
    "product_recommendation", ai_payload
)


Ở run_price_prediction_dss:

ai_payload = {**dss_result_raw, "table_data": dss_result_raw["table_data"][:20]}


rồi:

ai_result = self.ai_summarizer.summarize_with_ai("price_prediction", ai_payload)


Trong AISummarizer.summarize_with_ai thì nó lấy kpi_summary + table_data từ dss_result_raw và build prompt JSON cho LLM.

Nếu table_data rỗng hoặc KPI không đúng key mà fallback hiểu, thì _get_fallback_response() sẽ không tạo insight/action cụ thể và rơi vào 2 câu generic.

2. Thêm ai_input_stats để thấy AI nhận được gì

Mục tiêu: mỗi lần FE gọi /dss/*/run, response sẽ có thêm:

"ai_input_stats": {
  "scenario": "product_recommendation",
  "kpi_keys": ["num_source_products", "num_recommendations", "avg_similarity", ...],
  "table_rows_for_ai": 15
}


Để bạn nhìn 1 phát là biết: AI đang “thấy” bao nhiêu dòng & các KPI nào.

2.1. Sửa run_price_prediction_dss

Trong DSSService.run_price_prediction_dss, ngay sau chỗ:

bạn thêm:

            # NEW: summarize what AI actually received

                "scenario": "price_prediction",
                "kpi_keys": list(kpi_summary.keys()),
                "table_rows_for_ai": len(ai_payload.get("table_data", [])),
            }


Rồi phần return cuối cùng, thêm field:

        return {

            "items": data["items"],
            "total_count": data["total_count"],
            "ai_summary_insights": ai_summary_insights,
            "ai_recommended_actions": ai_recommended_actions,
            "generated_at": datetime.now().isoformat(),
            "ai_model_used": self.ai_summarizer.model

        }

3. Thêm logging chi tiết khi cần debug

Ngoài ai_input_stats trả về response, bạn có thể bật một chế độ debug sâu hơn qua ENV.

Trong AISummarizer.summarize_with_ai (ở đầu hàm, sau docstring) thêm:

    def summarize_with_ai(self, scenario: str, dss_result_raw: Dict[str, Any]) -> Dict[str, List[str]]:
        ...
        # Debug AI input when needed
        if os.getenv("AI_DEBUG", "0") == "1":
            try:
                kpi_summary = dss_result_raw.get("kpi_summary", {})
                table_data = dss_result_raw.get("table_data", [])
                logger.info(
                    "[AI_DEBUG] scenario=%s, kpi_keys=%s, table_rows=%d",
                    scenario,
                    list(kpi_summary.keys()),
                    len(table_data),
                )
                if table_data:
                    logger.info(
                        "[AI_DEBUG] first_row=%s",
                        json.dumps(table_data[0], ensure_ascii=False)[:1000],
                    )
            except Exception as e:
                logger.warning(f"[AI_DEBUG] Failed to log AI input: {e}")


Khi bạn set trong .env:

AI_DEBUG=1


log sẽ show rất rõ:

Scenario.

Danh sách key trong kpi_summary.

Số dòng table_data AI thấy.

1 sample row đầu tiên.

=> Nếu AI trả generic nhưng table_data đang = 0, hoặc KPI thiếu, bạn nhìn log là biết ngay.

4. Sửa fallback cho price_prediction để không còn bị “thiếu insight”

Hiện tại _get_fallback_response chỉ hiểu KPI dạng total_products, avg_price, total_reviews… nhưng KPI của price DSS đang là:

{
  "num_products",
  "num_with_recommendation",
  "current_revenue",
  "projected_revenue",
  "expected_revenue_uplift_pct",
  "avg_confidence",
}


Vì thế dù đã có KPI, fallback không đọc được, dẫn đến summary_insights rỗng và rơi vào 2 câu generic.

Ta chỉnh đoạn cuối của _get_fallback_response (trong ai_summarizer.py):

Hiện tại:

        if not summary_insights:
            if scenario == "product_recommendation":
                ...
            else:
                summary_insights.append(
                    "Hệ thống chưa đủ thông tin nổi bật để rút ra insight chi tiết, nhưng dữ liệu vẫn có thể dùng "
                    "cho các phân tích chi tiết hơn."
                )
        
        if not recommended_actions:
            if scenario == "product_recommendation":
                ...
            else:
                recommended_actions.append(
                    "Tiếp tục theo dõi dữ liệu trong các ngày tới và kết hợp với các báo cáo chi tiết "
                    "để đưa ra quyết định kinh doanh phù hợp."
                )


Bạn sửa thành (bổ sung case cho price_prediction):

        if not summary_insights:
            if scenario == "product_recommendation":
                # ... (giữ nguyên block hiện tại)
                ...
            elif scenario == "price_prediction":
                num_products = kpi_summary.get("num_products", 0)
                num_with_reco = kpi_summary.get("num_with_recommendation", 0)
                uplift = (kpi_summary.get("expected_revenue_uplift_pct") or 0.0) * 100
                avg_conf = (kpi_summary.get("avg_confidence") or 0.0) * 100

                summary_insights.append(
                    f"Hệ thống đang phân tích {num_products} sản phẩm có dự báo giá, trong đó {num_with_reco} sản phẩm có khuyến nghị điều chỉnh giá."
                )
                summary_insights.append(
                    f"Nếu áp dụng mức giá đề xuất, mô hình ước tính doanh thu có thể thay đổi khoảng {uplift:.1f}% so với hiện tại."
                )
                summary_insights.append(
                    f"Độ tin cậy trung bình của mô hình dự báo giá khoảng {avg_conf:.1f}%."
                )
            else:
                summary_insights.append(
                    "Hệ thống chưa đủ thông tin nổi bật để rút ra insight chi tiết, nhưng dữ liệu vẫn có thể dùng "
                    "cho các phân tích chi tiết hơn."
                )

        if not recommended_actions:
            if scenario == "product_recommendation":
                # ... (giữ nguyên block hiện tại)
                ...
            elif scenario == "price_prediction":
                recommended_actions.append(
                    "Ưu tiên xem xét nhóm sản phẩm có kỳ vọng tăng trưởng doanh thu cao để thử nghiệm điều chỉnh giá trước."
                )
                recommended_actions.append(
                    "Với các sản phẩm có confidence cao, có thể áp dụng điều chỉnh giá mạnh tay hơn (ví dụ 5–10%) so với nhóm còn lại."
                )
                recommended_actions.append(
                    "Theo dõi doanh thu thực tế sau khi triển khai điều chỉnh giá để hiệu chỉnh lại mô hình dự báo nếu cần."
                )
            else:
                recommended_actions.append(
                    "Tiếp tục theo dõi dữ liệu trong các ngày tới và kết hợp với các báo cáo chi tiết "
                    "để đưa ra quyết định kinh doanh phù hợp."
                )


=> Kể cả khi LLM trả mỏng, hoặc bạn tắt ai_mode="full", fallback vẫn đảm bảo ít nhất 3 insight + 3 action dựa trên KPI thật, không còn cảnh “thiếu dữ liệu” vô lý.

5. Sau khi sửa, test như thế nào?

Gọi lại /api/v1/dss/price/run hoặc /api/v1/dss/reco/run với ai_mode=full.

Xem trong JSON trả về:

ai_input_stats.table_rows_for_ai

ai_input_stats.kpi_keys

Nếu muốn log sâu hơn, set AI_DEBUG=1 trong .env rồi xem log backend để thấy sample row AI nhận.

Kiểm tra ai_summary_insights và ai_recommended_actions:

Với price DSS, dù ít data thì cũng phải có ~3 insight + 3 action dựa trên KPI.

Với reco DSS, fallback mới đã dùng KPI num_recommendations, avg_similarity, avg_orders_for_recommended, nên cũng luôn có nhiều câu hơn.
